# Torcherino AE



> 一句话版：这是一个把 Torcherino 的「时间加速」装进 ME 网格的 AE2 附属模组——加不加速、给谁加、加多快，都由你说了算。接 ME 网络、耗 AE 能量的 **AE 加速器**负责「精准加速」；免接线、不耗能的 **AE 加速火把**负责「区域加速」。



## 它是什么？



如果你玩过 Torcherino（加速火把），一定记得那根「插下去、周围一切都变快」的火把。本模组保留了这个想法，但做了个更「AE2」的变体：



- 加速可以是一项**网格服务**：把加速器接上 ME 网络、供上 AE 能量，就能在 GUI 里列出网络内所有可加速设备，逐台勾选、逐台调倍率，还能让合成 CPU 在合成期间自动「催」参与合成的机器。

- 加速也可以是一根**火把**：不需要网络、不需要能量，放下去扫出一个长方体范围，范围内的可加速目标统一变快。



两种方式都**不碰网络基础设施**——存储总线、P2P 隧道、能量元件这类「没有活可干」的方块不会被当作目标；真正会被加速的，是那些有逻辑在跑的机器。



## 它能给你带来什么？



| 内容 | 游戏内名称 | 它能做什么 |

| --- | --- | --- |

| 方块 | **AE 加速器** | 真正的 AE2 机器：接入 ME 网络 + AE 能量供电，4 格升级卡槽 + 1 格配置卡槽；GUI 列出网络内全部可加速设备与合成 CPU |

| 方块 | **AE 加速火把** | 免接线的区域加速源：以自身为中心扫一个长方体，GUI 调节加速倍数与 X/Z/Y 范围，带独立总开关 |

| 方块 | **AE 加速火把 I / II** | 基础火把的分级版，玩法完全一致，仅倍率上限固定为 ×64 / ×324 |

| 物品 | **AE 加速器升级卡 I / II / III** | 插入加速器升级槽，拉高「最高加速倍数」：各档首张按 ×2 / ×4 / ×8 全价生效，同档多张边际收益递减，可反复插 |

| 物品 | **加速器配置卡** | 把「加速器 + 一批设备/合成 CPU 组」的绑定关系存进一张卡：入槽自动注入加速，拔卡精确撤销 |



## 两条加速思路，怎么选？



| | **AE 加速器** | **AE 加速火把** |

| --- | --- | --- |

| 需要 ME 网络吗 | 需要，且要 AE 能量 | 不需要，也不耗能 |

| 加速范围 | 本网络内的设备（外加合成 CPU 联动） | 以火把为中心的长方体区域，可横跨多个网络 |

| 倍率粒度 | 每台设备单独设倍率 | 区域内统一一个倍率 |

| 怎么变强 | 插升级卡提高上限 | 换成分级火把 I / II（上限 ×64 / ×324） |



一句话：**追求精细控制 → 加速器；想「放下不管」→ 火把。**两者互不冲突，可以混用。



## 上手第一步：让加速器入网



1. 像普通 AE2 机器一样，把加速器接到 ME 网络（线缆 / 接口）上，并保证网络里有 AE 能量（能量元件、能源接收器等）。

2. 打开它的 GUI：顶部状态行实时显示**「工作中 / 已接入网络，等待能量 / 未接入网络」**，网络健康度一眼可辨；设备列表与合成 CPU 列表也在这同一屏。

3. **左键**设备条目 = 开启 / 停止对该设备的加速；**右键** = 弹出倍率调节（`1x ~ 当前最高倍率`，设为 `1x` 即取消）。列表支持搜索过滤。

4. 方块外观也带状态：接电后点亮发光的「工作带」（ONLINE），真正在干活时叠加流光粒子（WORKING）。



旁边就是 4 格升级卡槽与 1 格配置卡槽——下一步，把升级卡塞进去。



## 倍率从哪来？升级卡怎么堆？



加速器存在一个「最高加速倍数」，任何设备的倍率都不能超过它；而拉高它的唯一办法，就是**往升级槽里插 AE 加速器升级卡**。



基础倍率默认 **×4**，三档卡各带标称系数 **I = ×2、II = ×4、III = ×8**。为避免同档堆卡变成指数爆炸，采用「边际收益递减」：



```

同一档第 1 张：按标称系数全价放大（×2 / ×4 / ×8）

同一档第 n+1 张：实际倍率 = 1 + (第 n 张实际倍率 − 1) × cardDiminishing（默认 0.45）



最高倍率 = 基础(默认 4) × I 档复合增益 × II 档复合增益 × III 档复合增益

```



- 每档各插一张（混插）：`4 × 2 × 4 × 8 = 256x`

- 4 张 III 卡「满配」：约 **526x** (其实并非满配，你插2个II级再插2个III级试试看呢嘻嘻)；

- 不想要边际收益递减？把 `accelerator.cardDiminishing` 设为 `1.0`，即为 `基础 × 2^I × 4^II × 8^III`。



## 进阶玩法：让合成 CPU 当「监工」



在 GUI 的「合成 CPU」区**左键选中**一个 CPU，即开启**智能加速**：



- 该 CPU **执行合成期间**，加速器会自动提速参与合成的机器（分子装配室、压印机、充能器等），合成结束立刻停手——无需手工逐个勾选；

- 默认作用域 `crafting.smartAccelerateScope = ALL_ACCELERATABLE`：网格内所有可加速设备都会进入联动，因此第三方 AE 工作机器**零配置**即可兼容；

- 只想让「真正执行合成」的机器被联动？改为 `CRAFTING_MACHINES`（按 AE2 的 `ICraftingMachine` / `CRAFTING_MACHINE` 判定，内置压印机、充能器兜底，也可在 `grid.craftingMachineExtraTypes` 追加类型）；

- 服务端总开关：`crafting.smartAccelerateEnabled`（默认 `true`）。



## 再进阶：把加速方案写进一张卡



目标太多、手点太累？**加速器配置卡**可以把整套加速关系离线保存：



1. 手持卡 **Shift + 右键**一台加速器，把它绑定到卡上（改绑另一台会清空旧设备列表）；

2. 之后**右键**设备 = 加入 / 移出绑定列表；**右键合成 CPU 多方块** = 整组绑定 / 解绑（CPU 组只占一条）。单卡上限 64 条，满了会有提示；

3. 把卡**放入加速器配置卡槽**：卡上记录且在网内的设备会被自动注入加速；**取出卡**则精确撤销——绝不会误伤你在 GUI 里手工勾选的设备；

4. 绑定按「维度 + 坐标」识别设备，跨维度同坐标不会被认错。加速器本身只能接受「已绑定它自己」的卡（含维度校验），插错机器会被拒收。



> 配置卡是「即插即用」的：设备被拆、加速器被拆时，服务器会自动清理散落在玩家物品栏与卡槽里的相关绑定，不会留下指向空气的条目。



## 试试 AE 加速火把



- 不需要 ME 网络，也不消耗任何能量；放下就是一根「范围加速器」；

- 服务端以火把为中心扫描一个长方体，区域内**所有可加速目标**统一按当前倍率加速——它们可以分属不同 AE 网络，甚至根本不在任何网络里；

- 加速对象口径很宽：AE 网格设备、提供 ticker 的方块实体、以及依赖**随机 tick** 的方块（例如范围内的作物）都会被照顾到；空气、纯装饰方块与**其它加速火把**会被自动跳过（防止火把互相加速形成递归）；

- GUI 可调：**加速倍数**、**X / Z / Y 三个方向的范围半径**，还有一个**总开关**（关闭后火把熄灭，但倍率与范围设置保留）。基础火把默认 ×4、X/Z ±3、Y ±2，可调上限由服务端下发（默认 ×4、X/Z ±8、Y ±4）；

- 想要更高的倍率上限？换成 **AE 加速火把 I（×64）**或 **AE 加速火把 II（×324）**——这两级上限固定，不受 `torcherino.maxSpeed` 配置影响，放置时默认即为其上限。



## 一次堆到几百倍，服务器撑得住吗？



模组对性能做了多层保险，默认即开启、无需调参：



- **只加速有意义的机器**：网络基础设施被排除；火把侧只登记「真的可能被加速」的方块，每格只做一次 `getBlockEntity` 查询，跳过未加载区块；

- **区域扫描分片 + 自适应退避**：火把把一整圈扫描分摊到若干 tick（默认窗口 20 tick）完成；范围内长期无变化就逐轮退避到最长 200 tick；一旦有方块放置 / 破坏，立即被事件唤醒恢复密集扫描——大范围也不会在单个 tick 上打出主线程尖峰；

- **预算 + 两级自动节流**：`budget.tickCallsPerSource` 可给每台加速源设单 tick 调用上限（默认不限）；TPS 逼近 50ms 硬限时，`adaptive` 段会分级自动压预算；每台加速源还单独计量自己贡献的耗时（`rate.sourceMsLimit`，默认 15ms），超了就临时调低**实际生效倍率**——你在 GUI 里设的数值不会被改动，负载回落后实际倍率自动回升。



简单说：健康负载下它绝不干预你；极端高倍率拖垮 TPS 时，它会先「自降功率」保服务器。

（对机器加速时游戏卡是真没招）

## 遇到问题先自查，再求助



1. **加速器不工作？** 先看 GUI 状态行：`未接入网络` → 检查线缆与接口；`已接入网络，等待能量` → 检查网络供电与能量缓冲（`power.bufferFraction`）；状态正常却不出力 → 确认目标机器确实出现在列表里。

2. **列表里找不到目标机器？** 确认它是真·机器而不是存储总线这类基础设施；GUI 列表按周期刷新（默认 20 tick），稍等片刻或重开界面。

3. **AE加速火把不亮 / 没效果？** 检查总开关是否打开、倍率是否 > 1、范围是否没有被清零；升级后如遇异常，确认方块状态里带 `enabled` 属性。

4. **怀疑数值不对？** 把服务端配置 `debug.enabled` 设为 `true`（默认关闭），带着诊断日志排查。

5. 还不行？带上**版本号、截图、诊断日志与复现步骤**到 GitHub 仓库提问即可。

## 服务端配置速查



运行后在 `config/` 目录生成两份配置，修改后**热重载即生效**：



- `torcherino_ae_mod-server.toml` —— 服务端全部数值与行为；

- `torcherino_ae_mod-client.toml` —— 客户端界面 / 渲染开关。



| 分组 | 关键项（默认值） |

| --- | --- |

| `accelerator` | 基础倍率 `4` / 三档系数 `[2, 4, 8]` / 同档递减保留比 `0.45` / 上限 `-1`（不限） |

| `power` | 基础能耗 `1.0` / 每卡 `0.5` / 每设备 `0.5` / 停机缓冲占比 `0.9` |

| `torcherino` | 最大倍率 `4` / X·Z 最大半径 `8` / Y 最大半径 `4` |

| `budget` | 每台加速源每 tick 调用预算 `-1`（不限） |

| `adaptive` | TPS 节流开关 `true` / 收紧·回落阈值 `45 / 35 ms` / 起点档位 `256` 次 |

| `rate` | 单源耗时上限 `15 ms` / EMA 平滑 `0.25` / 收紧·放松比例 `1.0 / 0.7` |

| `cache` / `menu` | 目标缓存重建 / GUI 列表刷新周期 `20 / 20` tick |

| `grid` | 不可加速黑名单（默认三类基础设施）/ 合成机器兜底类型（压印机、充能器） |

| `crafting` | 智能加速总开关 `true` / 联动作用域 `ALL_ACCELERATABLE` |

| `debug` | 诊断日志 `false` / 采样间隔 `20` |

| `client` | 列表过滤缓存 `true` / 配置卡高亮 `true` |
